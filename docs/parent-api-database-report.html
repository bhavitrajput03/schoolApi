1. Database connection flow

Request schoolCode → admineyetab.dbo.SchoolConnection → tenant ConnectionString → tenant SchoolManagement-style database → current OwnerSession

The central registry chooses the tenant database. The tenant does not need an ApiSchool table. After tenant connection, parent/student/attendance/fee queries execute only in that selected tenant.

Academic session: every session-dependent API automatically selects the row where today falls between OwnerSession.StartDate and OwnerSession.EndDate.

5. Important SQL patterns

Current session

SELECT TOP 1 OwnerSessionID, SessionName, StartDate, EndDate
FROM OwnerSession
WHERE CAST(GETDATE() AS date)
      BETWEEN CAST(StartDate AS date) AND CAST(EndDate AS date)
ORDER BY StartDate DESC, OwnerSessionID DESC;

Parent-child authorization

SELECT TOP 1 ss.ClassID, ss.SectionID, ss.OwnerSessionID
FROM AppParentStudent link
JOIN StudentSession ss ON ss.StudentID = link.StudentID
WHERE link.AppParentID = @ParentID
  AND link.StudentID = @StudentID
  AND ss.OwnerSessionID = @CurrentSessionID
  AND ss.IsLeave = 0;

Attendance summary

SELECT COUNT(*) total,
       SUM(CASE WHEN AttType='P' THEN 1 ELSE 0 END) present,
       SUM(CASE WHEN AttType='A' THEN 1 ELSE 0 END) absent,
       SUM(CASE WHEN AttType='H/2' THEN 1 ELSE 0 END) halfDay
FROM AttItem
WHERE StudentID=@StudentID
  AND CAST(Dated AS date) BETWEEN @From AND @To;

6. Operational notes

  • All protected student endpoints first call the common parent-child authorization query.
  • Passwords may be legacy plain text once; successful login upgrades them to a secure PHP password hash.
  • Only token hashes are stored; raw bearer and refresh tokens are not saved.
  • Fee totals depend on the actual legacy column names present in each tenant. The implementation checks common aliases such as NetFee, Amount, FeeAmount, Discount and ReceiveAmount.
  • Payment rows are implemented, but real money collection still needs a selected gateway adapter and credentials.
  • New parent tables are defined in database/004_parent_app.sql. Runtime auto-bootstrap currently covers only the two teacher authentication support tables.
